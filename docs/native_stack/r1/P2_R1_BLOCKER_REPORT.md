# P2-R1 execution blocker

## Outcome

P2-R1 is **blocked before authoritative Development evaluation**. The source tag freezes 200 case identities, task/wind categories, seeds, issue offsets, and durations, but it does not freeze the deterministic resolver that turns those values into a physical cutter target, trajectory, wind time series, and force application.

The generic native runner cannot resolve a manifest case itself. It accepts a caller-supplied `ReferenceGenerator` and `disturbance_callback`. Consequently, two implementations can use the same manifest hash while running materially different physical experiments. Any baseline tuning on one newly invented resolver would silently change the accepted frozen benchmark.

## Preserved execution history

After the performance contract was frozen, 38 Development smoke executions used a provisional local resolver while checking controller plumbing. They produced no committed result artifacts and have no selection or scientific authority. Once the missing frozen semantics were identified, the provisional resolver and controller implementations were removed rather than being promoted as formal evidence.

No Native Holdout case was executed. No old Holdout was accessed. No paper was searched, selected, downloaded, implemented, or evaluated. V1-V10 evidence remains unchanged.

## Required decision

One of the following must happen before P2-R1 can restart:

1. identify an already-authoritative resolver that belongs to `native-stack-benchmark-v1`; or
2. authorize a dedicated R0 semantic-patch milestone that freezes the complete case resolver, validates it independently, creates a new source tag, and then restarts P2-R1 from that tag.

P2-R1 cannot legitimately define the missing resolver itself because its task card explicitly forbids modifying the frozen benchmark.
